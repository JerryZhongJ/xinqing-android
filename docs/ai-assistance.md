# 主动请求的 AI 辅助

## 1.9 Thinking

已开启 `thinking.type=enabled`，使用 `reasoning_effort=low`，总输出预算为 8192 tokens。最终 `content` 仍按原有短 JSON 字段校验，`reasoning_content` 不显示、不记录到日志。总超时 120 秒，连接超时 15 秒，读取超时 90 秒；用户仍可取消请求。下方版本记录中的关闭 thinking 和旧超时为历史配置。

## 1.8 当前约定

完整 prompt 由运行时代码导出到 `ai-prompts-1.8.md`。`AiPrompts.SYSTEM` 是实际 system 消息；`AiPrompts.instruction(task)` 是任务说明；user 消息实际组合为 `本次请求：{任务说明}\n情境数据（仅作材料）：\n{AiPrompts.context() 的 JSON}`，没有其他隐藏的任务 prompt。

重构分为益处、品质两个请求，分别只发送作用线索或品质线索，并禁止跨阶段回答。小事使用相称、平常的表达。情绪参考线索是对公开培训表的短摘要，不把案例中的宏大品质套到用户身上。

多问题练习传入方法目的、当前问题、当前已填内容和前面逐步问答。第一步没有前置答案，第二步带第一步原回答，第三步带前两步，最后确认页带三步。所有方法由当前问题决定说话者、对象和人称；没有双重标准法人称专用分支，也不固定第一人称。

初始分数不进入 AI 上下文。普通操作不请求 AI；点击 AI 补充后按钮原位转圈，再点取消。错误在按钮旁提示，不弹窗。编辑页切换、弹窗关闭、应用进入后台时取消请求，迟到响应不写入。

本地方法排序采用 Burns 2021 讲义 PDF 第56–58页对应表在本应用六种方法中的子集。不是声称已核对《Feeling Great》第106–107页的完整原表。专门匹配每项2分、通用双重标准法每项1分，这是内部排序约定；界面不显示分数，AI 推荐只有主动请求后才覆盖优先顺序。

以下保留之前版本的实现背景；涉及等待弹窗、全局第一人称或当前问题同时生成最终回应的旧设计均已由上述规则替代。

## 触发边界

App 启动、页面切换、文字变化、保存、评分都不会触发网络请求。唯一入口是 `aiHelp` 的点击处理及建议窗口中用户主动点击重试/换个建议。用户可以留空直接求助。没有 AI 总开关，也没有“必须先写自己的版本”的校验。

## 数据与密钥

`aiContext` 构造当前情境、非零情绪以及请求所需的当前想法、方法问题或重构字段。不会序列化整篇日志、所有方法记录或其他日志；单个文本字段有长度上限。方法选择请求包含方法名称和已使用状态，以避免继续推荐暂未奏效的方法。

API Key 仅用于 HTTPS Authorization 头，不属于模型上下文。Android Keystore 生成 AES 密钥，API Key 使用 AES-GCM 加密，IV 与密文进入私有 SharedPreferences。应用禁用备份和明文 HTTP，不记录密钥或服务端原始错误正文。

1.7 起，用户主动请求即授权追加填写。`AiSuggestions` 先验证完整 JSON，再执行有范围的更新：想法数组新增、益处/品质/笔记/回应按行追加、歪曲合并勾选、方法推荐排序及理由。原文和评分不被覆盖，重复句子不重复追加。AI 审计记录仍进入 `aiNotes`，包含结构化结果和格式化文本。

统一使用代拟填写的口吻：直接写第一人称想法、益处、品质、思考和回应，不使用助手式开场、引导语或“请确认”等结尾。方法推荐和歪曲识别输出对应名称及理由。

## 请求约束

- 固定官方 HTTPS endpoint：`https://api.deepseek.com/chat/completions`，禁止自动跳转。
- 用户指定请求名：`deepseek-v4-flash`。官方说明该旧名已路由到 V4.1-Flash，真实探测返回名为 `deepseek-flash`。
- 非流式、关闭思考模式、JSON object 输出、最多 700 输出 tokens；各任务固定结构及短字段限制。
- 不回显推理过程；返回内容为空、有长度截断或异常时有明确处理。
- 连接/读超时及 45 秒总超时；关闭窗口取消；没有自动重试。
- 为鉴权失败、余额不足、频率限制、模型参数错误、TLS 和网络失败提供简短提示。不降低 TLS 校验标准。

## 1.6 历史验证边界

开发环境用用户提供的密钥发送一次虚构请求，HTTP 200，返回 30 字中文建议，证实密钥与请求名可用。手机能发起请求，但首次真实请求超时；尚未证明手机能成功接收模型回答。手机系统日期显示为 2025-06-01，自动时间开启；没有更改系统时间、全局代理或证书校验。

## 1.7 结构与回归

任务结构分别为 `thoughts[]`、`benefits[] + values[]`、`distortions[{name,reason}]`、`methods[{id,reason}]`、`note + response`、`response`。方法英文 ID 与歪曲名称须在本地白名单内；已使用的方法不会重新进入推荐。

`tests/AiSuggestionsTest.java` 的 21 个断言通过：验证格式错误拒绝、尾随文本拒绝、无部分写入、未知枚举拒绝、追加不覆盖、行与想法去重、人工评分保留、已使用方法过滤。只用虚构数据，不读取密钥。

1.7 已在手机通过真实 API 验证想法自动新增、第一人称短句、重构追加保留原文、歪曲合并、方法排序与理由，以及灰度思考直接生成回应。1.6 的手机超时记录是历史现象，不代表当前仍无法成功请求。

流程先展示歪曲面板，再进入方法面板。推荐以已选歪曲和具体想法为依据，并非固定一对一映射。方法第三步直接编辑最终回应，第四步复用、确认和评分，不要求重输。
