# 通用 Prompt 修订说明

本轮移除了写在通用指令中的具体生活案例、词语黑名单、固定开头和正向重构品质必须恰好一条的要求。保留 JSON 结构、最大长度、字段范围、角色与依据约束。

实际 prompt 全文见 [ai-prompts-1.8.md](ai-prompts-1.8.md)。该文档由 `AiPrompts` 的运行时字符串导出；动态上下文使用占位符说明，不是每次请求固定发送的示例。

## 新约束的目的

- 益处：分析情绪或自动想法可能起到的作用，不分析事件本身的收获，不提前进行认知反驳。
- 品质：描述有材料支持的具体在意，不由一次经历推断整个人的人格或人生意义。
- 语言：范围、强度与实际材料相称。没有禁止某几个词，也不把所有事件都当成小事。
- 双重标准法：第一步扮演用户，对假想朋友直接说话；角色变化不是编造自我披露或朋友经历的许可。第二步比较已有两套标准，第三步才形成对自己的回应。
- 角色规则统一：以上视角由方法的当前问题决定，不再为双重标准法设置人称专用分支。所有方法共享当前问题/形成回应指令，上下文包含方法目的、当前问题和此前回答。
- 上下文：保留当前材料和之前实际填写的问答，不在材料不足时补写事实。

## 回归案例与评价

具体案例保留在 `tests/PromptGeneralityTest.java`：物品遗失、工作失误、人际冲突、重要丧失。自动检查案例和词语黑名单没有进入共享指令，各案例的当前事件及此前回答正确进入上下文。

这些检查验证 prompt 和数据组装，不等于验证了模型输出质量。后续跨场景实测应按以下标准人工判断，而不是靠词语命中判定好坏：

1. 回答的是不是当前字段，是否越到另一个阶段？
2. 是否分析情绪/想法的作用，而非给不幸事件找好处？
3. 推断是否有依据，是否与事件及用户表达的强度相称？
4. 是否编造经历、行为频率或他人的评价？
5. 角色及称呼是否正确，是否使用了已有回答？

本轮不调用外部模型，不自动覆盖安装手机版本；先提供源码和完整 prompt 供审阅。
